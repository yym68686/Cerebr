# 内置 MCP 工具调用与 Responses API（功能提案）

这是一份不绑定个人服务商的实现提案，目标是让 Cerebr 在保持现有对话界面的同时，使用 HTTP MCP 工具完成“模型提出调用 → 用户授权（按策略）→ 工具结果 → 模型续答”的多轮流程。

## 功能范围

- Streamable HTTP 和旧版 HTTP + SSE：初始化、会话恢复、工具分页、超时、中断。
- MCP 设置页：服务器 URL/认证头、常见 MCP JSON 导入、工具刷新、服务器开关和逐项工具开关。
- 工具调用卡片：参数、结果、状态、图片；对话历史保存工具调用，继续聊天时可恢复 API transcript。
- Chat Completions 与原生 Responses API：函数调用、流式返回、公开推理摘要以及当前轮的加密推理续接。
- 自动识别 Responses 实际响应体，兼容响应头误写成 JSON、实际返回 SSE 的兼容服务；收到终止事件即结束读取，不等待连接 EOF。
- 支持带服务商前缀的模型名识别思考档位，不硬编码某个个人服务商、API 路由或模型。

没有改变已有第三方插件系统 API、模板或插件市场，所以不需要同步修改插件模板或 bundled marketplace 快照。

## 安全默认值和权限

默认只读工具自动执行，其他工具逐次确认。提供“所有工具确认”“只读自动”“始终允许所有已启用工具”，以及单项工具“始终允许”；自动执行是用户显式选择，不是上游默认。

始终允许不等于启用全部工具。已停用的服务器和工具不会提供给模型。刷新工具列表时保留用户的单项选择；列表经过筛选的情况下，新发现的工具默认不启用。旧版 SSE 返回跨域消息 endpoint 时拒绝转发认证头。

新 API 和 MCP 凭证只写扩展本地存储，不新上传到浏览器账号同步存储；兼容读取已有的旧设置，不自动清除用户历史同步数据。

工具返回内容只作为数据，不作为新的系统指令。工具结果在 UI 中按文本渲染，图片使用实际返回的图片数据。

## 可选的本机配置导入

`cerebr.local.example.json` 只提供空密钥和保留示例域名，不包含可用账号。正常使用可直接在设置页填 API/MCP，无需初始化文件。

如需预置配置，可在本机另建 `cerebr.local.json`（已 Git 忽略）。`seedVersion` 控制一次性应用；默认保留已有 MCP 设置和额外自建项目。显式 `mcp.syncExisting: true` 可在版本更新时同步 seed 所属服务器和设置，不触碰聊天记录。真正含凭证的文件不能打进公开发行包。

通用助手可配置用户消息模板、固定消息发送时间和上下文限制。时间附加在用户消息中，而不是每轮改写系统提示词，减少动态前缀对缓存稳定性的干扰。这不等于承诺服务商缓存已经命中。

## 本地验证

无需账号或联网调用即可运行协议/行为测试：

```sh
node --experimental-default-type=module scripts/test_mcp.mjs
```

如需设置页/卡片 DOM 冒烟测试，先在临时目录安装 `linkedom`，将 `CEREBR_TEST_DOM_MODULE` 指向其 `esm/index.js`。CI 会执行这组测试，不需要服务密钥。

覆盖 SSE 分块、HTTP 会话恢复、旧 SSE、中断与权限确认、跨域认证保护、工具开关、历史和图片、两种 API 协议、初始化迁移、消息时间稳定性和 DOM 渲染。

## 当前边界与待验收项

- 未把 Node/mock 测试冒充为浏览器 GUI 验收；Chrome/Edge 侧栏、Firefox 和完整浏览器 API 集成仍需作者评估。
- 有些 MCP 服务在浏览器调用时会返回 `403: Invalid Origin header`。服务端需要正确配置扩展 Origin 白名单与 CORS；本提案不通过关闭来源检查绕过安全边界。
- 浏览器不能直接启动本机 stdio MCP 程序。本提案没有安装本机代理、原生执行宿主或服务器。
- 未引入个人 GitHub 私库更新器、Native Messaging、计划任务或远程加载代码。扩展更新应遵循作者原有的商店/发行流程。
- 未改动 manifest 版本和 `v/` 生成物。扩展直接加载未版本化源码；若作者同时发布 Web 版，需要按现有发布流程生成对应的版本化资源。
- UI 文案目前沿用开发时的中文，新文案完整 i18n 待维护者决定。

建议按“协议客户端与设置 → 多轮调用/卡片 → Responses adapter → 导入与迁移”分模块评审。可以先讨论 API 和权限设计，再决定是否合并或拆成多个 PR。
