# Cerebr Desktop

桌面宿主放在同一仓库的 `desktop/` npm workspace，采用 Electron、TypeScript、Vite 和 Electron Forge。Web、浏览器扩展和桌面端共享 `src/main.jsx`，桌面端同样加载构建后的 `index.html → boot.js → web-manifest.json`。

## 开发与打包

推荐 Node.js 24，并先初始化 htmd 子模块。

```sh
npm ci
npm run dev:desktop
npm run check
npm run check --workspace cerebr-desktop
npm run package:desktop
```

macOS 产物在 `artifacts/desktop/`，包括 `.app`、DMG 和 ZIP。Windows 请在 Windows 上运行相同命令，Forge 会生成 ZIP 和 Squirrel 安装程序。架构默认采用构建机器的架构；Intel Mac 可在相应机器上构建或向 Forge 传入 `--arch=x64`。当前本机验证平台为 macOS arm64，Windows 尚需实机验收。

当前 CI 生成未签名、未公证的安装包；正式签名需要 Apple Developer / Windows 证书，偏好设置中的「检查并更新」会自动下载最新正式版，保存会话并重启安装。打包时同步维护根目录、两个扩展 manifest 和 `desktop/package.json` 的版本号。

## 与浏览器扩展配对

1. 启动 Cerebr 桌面应用，打开「＋ → 偏好设置 → 桌面同步」。
2. 将桌面端显示的十位配对码输入同一电脑上 Cerebr 扩展的相同页面。
3. 首次连接合并两端历史，保留已有记录。大历史首次同步可能需要一些时间。
4. 两端各点击「校验完整性」，对比对话数、消息数和 SHA-256。校验覆盖图片、引用、思考内容等完整记录，结果显示对应的校验时间。

配对后不再要求输入代码。桌面退出期间，扩展仍然正常保存历史；桌面重新启动后扩展自动重连，按版本补齐变更。macOS 关闭窗口会保留后台同步服务，使用「退出 Cerebr」才结束服务。扩展设置中的「断开同步」会移除本端配对凭据，不删除任何历史。

同步包括完整聊天对象、图片、Markdown/思考内容、引用、聊天文件夹与分配、草稿、阅读进度及 YouTube 字幕缓存。正在生成的状态通过独立消息传递，接收端的聊天列表显示转圈；消息正文随存储检查点更新。当前选中的聊天和浏览器标签页 ID 保持各端独立。草稿与阅读进度的数据会同步，读取时仍遵循原有的草稿恢复和滚动恢复行为。

API 密钥、地址、模型、参数和系统提示词通过已配对的本机通道自动双向同步。每个 API 配置单独版本化；首次合并保留两端不同 ID 的配置，未配置的桌面占位项不覆盖浏览器设置。新对话的默认模型仅保存在本机，登录、配置同步和浏览历史不会改写它；旧 `cerebr_api_selection_v1` 仅用于没有本地选择的新设备初始化。

每个对话的 `modelSelection` 保存配置 ID 和模型名，随聊天同步；API 密钥不复制到对话中。主动选择模型会更新当前对话和本机以后新建对话的默认值，其他旧对话保持原值。请求、重试和重新生成均读取对话的模型；配置 ID 丢失时要求用户重新选择，不静默使用其他模型。旧版本没有记录逐对话的历史模型，升级时会保留本机的旧选择作为这些对话的固定回退值，实际继续提问或主动选模型时再保存绑定；单纯浏览历史不会发布推测的模型选择。无法推断此前已经丢失的真实模型。原有 Chrome sync API 配置继续兼容，但不再投影或导入全局选择。插件配置和整站偏好不在该同步范围内。当前版本没有向渲染页面开放任意文件读写或命令执行 API；后续此类能力应经受控主进程接口提供。

## 数据与同步边界

- 本地通道仅监听 `127.0.0.1:43179`，校验扩展 Origin，使用一次性十分钟配对码换取按 Origin 绑定的随机凭据。没有云端上传、局域网监听或账号服务。
- Chromium 的 IndexedDB 保留原有存储键。消息与待同步版本在同一事务写入；删除保留 tombstone，过期副本和旧索引不会复活已删除对话。
- 独立 utility process 用 SQLite WAL 保存同步副本，避免网络与 SQLite 操作阻塞 Electron 主进程。每次启动仅交换版本清单，按需传送变更的完整记录。
- 同时编辑同一对话时按单调时钟和稳定 actor 排序，最新记录成为当前值。不同 actor 的被替代版本保存在 SQLite `revisions` 表，可用于人工恢复；当前没有逐消息 CRDT 合并或冲突恢复 UI。
- 单条传输记录上限 128 MiB；超大记录会触发连接错误，应减少单个对话中的图片体积后再同步。
- 整体历史完整性校验按需执行；普通流式更新只计算轻量统计，避免反复扫描全部图片数据。

macOS 数据目录：`~/Library/Application Support/Cerebr/`。Windows 数据目录由 Electron 的 `app.getPath('userData')` 决定，通常为 `%APPDATA%/Cerebr/`。其中 `history-sync.sqlite` 保存同步副本和冲突版本，`desktop-sync.log` 记录宿主服务错误；渲染端 IndexedDB 是本机 UI 使用的数据副本。移动或重新打包 `.app` 不改变数据目录。

## 验证

`tests/desktop-sync.test.js` 覆盖图片/引用/思考传输、离线合并、延迟确认、删除与旧索引、冲突版本和两种运行时一致的摘要。存储回归测试覆盖远程删除后不从旧 Chrome storage 恢复。

桌面构建还会执行 `desktop/verify-build.mjs`：使用临时数据库和随机本机端口，实际运行打包后的同步服务，验证配对、1 MiB 消息往返、IPC 与完整性校验，确保没有误将 Node WebSocket 服务打包成浏览器实现。该检查不会访问用户的历史数据库。



## 网页问答与桌面界面

配对后的扩展通过受限网页桥接提供标签页列表、当前网页、分组及正文提取。桌面共用扩展的多选界面，并在扩展侧保存对话的网页选择和自动引用偏好，所以同一对话在两端共享选择。PDF 和字幕仍走已有内容提取链路。断开连接后隐藏网页入口及来源标签；配对信息与历史数据保留。

桥接只允许读取标签页、提取明确指定的页面及更新网页选择，不允许任意扩展消息或脚本执行。请求绑定到提供标签页的具体连接，换浏览器或断线后不会把旧的标签页 ID 发到另一个浏览器。多个浏览器同时连接时使用最早连接且支持桥接的浏览器；断线后自动选择剩余连接。

桌面采用无边框窗口，macOS 保留原生窗口按钮，其他平台提供最小化、最大化和关闭按钮；聊天页不设置覆盖内容的独立标题栏，窗口可从侧栏顶部拖动；进入 API 设置、偏好设置等页面时，导航栏直接从应用上边缘开始，并承担窗口拖动，不保留独立标题栏或顶部占位。窄窗口中的原生窗口按钮与返回按钮在同一行水平避让。侧边栏去除品牌标题，菜单开启时高亮固定在操作对象上。

桌面同步偏好采用紧凑卡片，显示连接状态、对话与消息统计、最近同步；已连接时默认收起配对码和摘要详情。只在需要连接另一个浏览器或展开校验详情时显示这些信息。


## GitHub Actions 自动构建与发布

工作流 `.github/workflows/release.yml` 会在 `main` 推送、相关 PR 和手动运行时构建并保留 14 天的安装包产物。三个桌面构建目标为：

| 系统 | 架构 | 安装包 |
| --- | --- | --- |
| macOS 15 runner | Apple Silicon / arm64 | DMG、ZIP |
| macOS 15 Intel runner | Intel / x64 | DMG、ZIP |
| Windows 2025 runner | x64 | Setup.exe、ZIP |

发布步骤：

1. 同步修改 `package.json`、`desktop/package.json`、两个扩展 manifest 的版本，并更新 `package-lock.json`。
2. 提交并推送代码，再推送对应版本标签，例如 `git tag v2.5.15`、`git push origin v2.5.15`。
3. 版本检查、测试、扩展和全部桌面构建成功后，工作流创建草稿 Release，上传全部包和每个平台的 SHA-256 文件，最后发布。构建失败不会发布残缺版本。

也可在 Actions 手动运行，勾选 `publish` 发布所选 commit 的版本。已有同名标签必须指向该 commit；已有公开 Release 不会被覆盖。上传中断留下的草稿可重跑完成。无需额外 PAT，发布作业使用仓库的 `GITHUB_TOKEN`，只有该作业具备 `contents: write` 权限。

### 客户端更新

桌面偏好设置底部提供「检查并更新」。点击一次后，主进程读取本仓库最新正式 Release，比较数字版本，下载对应架构的包并验证文件长度和 SHA-256。下载期间显示进度；遇到网络、校验或保存失败时保留应用运行，可重试。下载完成后等待本机回答和消息编辑结束，保存草稿、阅读位置、聊天与 API 配置，再安装重启。当前不在启动时擅自安装更新。

macOS 当前未使用 Developer ID 签名，无法使用要求签名的 Squirrel.Mac。更新器从官方 GitHub Release 下载 ZIP，在应用所在卷预备新 bundle、校验 bundle ID 和版本，退出后用独立 helper 交换目录并重新启动。新 React 会话确认启动成功后才清理旧 bundle；安装失败回滚。不会移除 quarantine、改变 Gatekeeper 或请求管理员权限。需将应用安装到当前用户可写的 Applications 目录，不能从 DMG 或 App Translocation 更新。以后配置正式签名后可切换到系统更新机制。

Windows 使用 Squirrel 安装。CI 额外发布 `RELEASES` 和 `Cerebr-<version>-full.nupkg`，并将它们纳入 SHA-256 清单；客户端校验后让 Electron 内置更新器读取本地更新目录，安装并自动重启。ZIP 便携运行需先用 Setup.exe 安装。Windows 安装与实际重启仍需 Windows 实机验收。

更新主机能力只通过受限 preload 暴露检查、状态和已保存确认，不接收渲染端提供的下载 URL 或命令。不改动历史数据库和配对凭据。检查、请求重试、准备安装与失败阶段记入 `desktop-update.log`，临时包在用户数据目录的 `updates/`。

正式桌面包启动 15 秒后自动检查，此后每 6 小时检查最新版。后台下载完成进入 `downloaded`，用户点击「重启并更新」才保存并重启；主动点击「检查并更新」仍会在下载完成、回答结束且保存完成后自动安装。网络中断、超时和 GitHub 5xx 最多即时尝试三次，随后进入 `paused`，联网时每分钟重试；限流和完整性错误不会频繁重试。

更新包按版本、平台、架构保存，支持最多 4 路 HTTP Range 分段下载。每段文件长度就是断点，应用重启后仍能续传；元数据包含 URL、总长度与 SHA-256，版本或内容变化不会拼接旧数据。服务端忽略 Range 时回退完整单流下载。合并后校验完整大小和 SHA-256，再原子改名为安装文件，校验失败删除分段而不是安装。Windows 还验证 Squirrel 的 SHA-1 清单。

点击「新的对话」只创建可复用的本机工作会话。空会话及其模型选择存在不参与同步的工作状态键中，不进入聊天索引或历史记录；草稿、图片和网页选择继续保留。首条消息加入时才写入历史并参与多端同步，准备发送时取消或提取网页失败不会产生空历史。旧版本产生的零消息记录从列表隐藏，原始数据保留。

### 实时同步与窗口交互

连接期间，发送的问题、Loading State、思考 Markdown 和流式正文通过独立的临时通道立即发送，正文分片沿用 100ms 节流；不必等待历史落盘。持久化同步仍负责离线恢复、完整历史和冲突版本。实时视图带请求 ID 和序号，不让延迟的历史检查点覆盖更新的流式文本。重新连接可接收当前生成快照。

折叠侧边栏后不保留窄栏。标题区按钮位于 macOS 红绿灯右侧，悬浮临时展开，点击固定展开或折叠；窄窗口继续使用全屏导航。聊天和设置顶部共用透明拖动区域，其矩形避开侧边栏按钮，不以 z-index 覆盖原生拖动命中区域。聊天页面全选限定正文，编辑框仍使用原生全选。切换有网页引用的对话时，缓存标签与加载占位保持输入框高度稳定。

## 账号云同步

偏好设置的「同步」提供用户名密码注册、登录、退出及完整性校验；账号不出现在聊天、侧栏或其他页面。网页登录站点、桌面和扩展均连接 `https://cerebr-sync.fugue.pro`。独立服务源码位于同级 `cerebr-sync/`，使用 PostgreSQL 和 Compose，由 Fugue 托管。

先将数据与版本持久化到本地 IndexedDB，再通过已登录的云连接发送。本机配对仍为独立通道；每条连接独立记录确认版本，云端失败不会阻塞本地保存，本机确认也不会吞掉待发云端的版本。两种连接收到的新记录也会继续传递给另一端。账号会话、设备 ID 和登录状态不参与复制；退出保留本地内容，重新登录会合并本机与该账号数据。

同步包含聊天、图片、思考内容、引用、草稿、阅读进度、文件夹以及 API 设置。Web API 配置同样迁移到版本化记录。实时生成状态走同一套请求 ID/序号通道，持久化历史仍处理断线恢复和删除墓碑。

同步偏好设置合并云端和本机连接为一个区域，共享一组实时本机统计；账号登录与本机配对均按需展开。两条连接的状态、最近同步时间与校验操作仍相互独立。应用更新使用相同的紧凑行布局展示版本、下载进度和重启操作。


### 并发回复与阅读交互

每个对话独立管理请求、取消和实时同步序号。切换或新建对话不会取消其他对话的回复；停止按钮只停止当前对话，删除对话时才取消该对话的请求。收到 SSE `[DONE]` 或非空 `finish_reason` 即完成回复，不继续等待 HTTP 连接关闭。同步接收端记录请求开始时间与结束状态，避免本机/云端迟到的进度重新点亮已完成对话。

`Cmd+F`（其他平台 `Ctrl+F`）查找当前聊天正文；Enter / Shift+Enter 切换匹配，Esc 关闭。匹配使用独立高亮层，不修改 Markdown 或编辑器内容。聊天滚动条与侧边栏使用相同的细滚动条。网页来源列表里的地址使用外部链接，Electron 交给默认浏览器打开。

聊天区域支持拖入图片及 TXT（最大 10 MB）。TXT 读取为可编辑的纯文本，追加至当前草稿；异步读取时切换/清空草稿会丢弃尚未插入的文件。插件网页图片拖放通过 iframe 发起的一次性请求读取，避免重复插入，并显示拖入/读取反馈。


### TXT 附件与大文本编辑

TXT 拖入或通过加号选择后，显示为输入框上方可移除的文件标签；正文编辑区只保留提问。文件随草稿保存、切换对话恢复并参与本机/云端同步。发送时完整文本进入标准消息 content，消息只额外记录文件名、大小、文本长度等显示元数据，因此旧版客户端仍可读取内容。再次编辑消息会恢复附件与提问，取消编辑会恢复之前的草稿。文件最大 10 MB。

长文本粘贴采用单个 pre-wrap 文本节点，避免每行创建文本节点和 br。草稿读取直接遍历原有 DOM，不再序列化和重新解析整段 HTML。全选删除兼容浏览器位于文本节点内、忽略末尾换行的选区，并支持 Cmd/Ctrl+Z 撤销和 Shift+Cmd/Ctrl+Z / Ctrl+Y 重做；普通局部编辑与 IME 继续使用原生行为。
